# 비교과 FLEX-day 온라인 접수 시스템 — 배포 가이드

학과 담당자는 **로그인 없이 링크로 바로 신청서를 제출**하고, 센터 관리자는 **PIN으로 들어가 접수 현황을 검토·승인/반려**하는 구조입니다.
구글 스프레드시트를 DB로 쓰고, Apps Script를 API 서버로 쓰는 방식이라 별도 서버 비용이 들지 않고, 기존에 쓰시던 비교과 중복검사 시스템·졸업요건 자기진단 시스템과 같은 패턴입니다.

## 구성 파일

| 파일 | 역할 |
|---|---|
| `index.html` | 학과 신청 폼 + 센터 관리자 화면 (이 파일 하나를 그대로 배포) |
| `Code.gs` | 구글 스프레드시트에 붙일 Apps Script 백엔드 (제출/조회/승인·반려 API) |

## 1단계 — 스프레드시트 만들기

1. Google Sheets에서 새 스프레드시트를 만듭니다. (이름 예: `FLEX-day 신청현황`)
2. 시트 자체의 열 이름은 신경 쓰지 않아도 됩니다 — 처음 신청이 들어올 때 `Code.gs`가 `신청현황`이라는 시트를 자동으로 만들고 헤더까지 채웁니다.

## 2단계 — Apps Script 붙여넣기

1. 스프레드시트 메뉴에서 **확장 프로그램 → Apps Script**를 클릭합니다.
2. 기본으로 열려 있는 `Code.gs`의 내용을 모두 지우고, 이 폴더의 `Code.gs` 내용을 그대로 붙여넣습니다.
3. 상단의 `ADMIN_PIN = 'CHANGE_ME_1234'` 부분을 원하는 PIN으로 반드시 변경합니다. (센터 관리자만 공유받는 값입니다.)
4. `Ctrl/Cmd + S`로 저장합니다.

## 3단계 — 웹 앱으로 배포

1. Apps Script 화면 오른쪽 위 **배포 → 새 배포**를 클릭합니다.
2. 유형 선택에서 **웹 앱**을 선택합니다.
3. 다음과 같이 설정합니다.
   - 실행 계정: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자** (로그인 없이 제출받으려면 이 설정이 필요합니다)
4. **배포**를 누르면 `https://script.google.com/macros/s/xxxx/exec` 형태의 URL이 발급됩니다. 이 URL을 복사해 둡니다.
   - 이후 `Code.gs`를 수정하면 **배포 관리 → 배포 수정 → 새 버전**으로 다시 배포해야 반영됩니다. URL은 바뀌지 않습니다.

## 4단계 — index.html에 배포 URL 연결

1. `index.html`을 텍스트 에디터로 엽니다.
2. 아래 줄을 찾습니다.
   ```js
   const APPS_SCRIPT_URL = 'REPLACE_WITH_YOUR_WEB_APP_URL';
   ```
3. `REPLACE_WITH_YOUR_WEB_APP_URL` 부분을 3단계에서 복사한 `.../exec` 주소로 바꿉니다.

## 5단계 — 페이지 게시

가장 간단한 방법은 기존에 쓰시던 방식대로 **GitHub Pages**에 올리는 것입니다.

1. GitHub 저장소를 하나 만들고 (또는 기존 저장소 활용) `index.html`을 올립니다.
2. 저장소 설정의 **Pages**에서 배포 브랜치를 지정하면 `https://<계정명>.github.io/<저장소명>/` 형태의 주소가 생깁니다.
3. 학과에는 이 주소를, 센터 관리자에게는 **같은 주소 뒤에 `#admin`을 붙인 주소**(예: `.../index.html#admin`)와 PIN을 함께 공유하세요. 관리자 화면은 페이지 하단의 "관리자 화면" 링크로도 들어갈 수 있습니다.

GitHub Pages 대신 학교 내부 웹 호스팅이 있다면 그곳에 `index.html` 하나만 올려도 동일하게 동작합니다.

## 관리자 로그인이 "연결 중 오류가 발생했습니다"로 안 될 때

거의 대부분 아래 두 가지 중 하나입니다. 위에서부터 순서대로 확인해 보세요.

1. **`index.html`의 `APPS_SCRIPT_URL`이 아직 배포 주소로 안 바뀜.**
   기본값 `REPLACE_WITH_YOUR_WEB_APP_URL`이 그대로 남아 있으면 관리자 화면에서 "Apps Script 주소가 아직 연결되지 않았습니다" 메시지가 뜹니다. 3단계에서 발급받은 `.../exec` 주소로 정확히 바꿨는지 확인하세요.
2. **`Code.gs`를 수정(예: `ADMIN_PIN` 변경)한 뒤 새 버전으로 재배포하지 않음.**
   Apps Script는 `Ctrl/Cmd+S`로 저장만 해서는 이미 배포된 웹앱에 반영되지 않습니다. **배포 → 배포 관리 → 배포 수정(연필 아이콘) → 버전: 새 버전 → 배포**까지 해야 바뀐 PIN이 실제로 적용됩니다. (주소는 바뀌지 않습니다.)

그래도 안 되면 배포 화면에서 **액세스 권한이 "모든 사용자"로 되어 있는지**, 웹앱 URL을 브라우저 주소창에 직접 붙여넣었을 때(`.../exec?action=ping`) `{"ok":true}`가 뜨는지 확인해 보세요. 이 응답이 아예 안 뜬다면 배포 자체가 안 된 것이고, `{"error":"unauthorized"}`가 뜬다면 배포/URL은 정상이고 PIN이 서로 다른 것입니다. 브라우저 개발자도구(F12) 콘솔에도 실패 원인이 출력되도록 해 두었으니 참고하셔도 됩니다.

## 신청서 항목

학과 담당자가 입력하는 항목은 다음과 같이 구성해 두었습니다. 실제 운영 중이던 네이버폼/서면 양식과 다른 부분이 있다면 말씀해 주세요 — 항목을 맞춰 수정해 드릴 수 있습니다.

- 신청자 정보: 학과(부)명, 교수명
- 프로그램 정보: 희망 일자·시간, 희망 장소, 참여 대상, 예상 인원, 센터 협조·지원 요청사항, 비고

## 검토·승인 흐름

- 접수 즉시 상태는 **접수**로 시작합니다.
- 관리자 화면에서 신청 건을 클릭하면 상세 내용을 보고 **검토중 / 승인 / 반려**로 상태를 바꿀 수 있습니다. (반려 시에는 사유 입력이 필수입니다.)
- 관리자 화면 상단에서 전체/접수/검토중/승인/반려 건수를 바로 확인할 수 있고, 학과명·교수명·신청번호로 검색·필터링이 가능합니다. (문의 전화가 오면 신청번호를 검색창에 붙여넣으면 바로 찾아집니다.)
- **엑셀 다운로드** 버튼으로 현재 화면에 표시된 목록을 그대로 `.xlsx`로 내려받을 수 있습니다. (보고용 자료 취합에 활용하세요.)
- 원본 데이터는 항상 연결된 구글 스프레드시트의 `신청현황` 시트에 쌓이므로, 필요하면 시트를 직접 열어 확인·가공하셔도 됩니다.

## 접수 마감/재개

관리자 화면 맨 위 **접수 상태** 카드에서 언제든 접수를 마감하거나 다시 열 수 있습니다. 마감 상태에서는 학과 화면에 폼 대신 "비교과 FLEX-day 접수가 마감되었습니다" 안내만 표시되고, 혹시 폼이 열려 있던 학과가 그 상태에서 제출을 시도해도 서버(Apps Script) 쪽에서 한 번 더 막아줍니다. 이 상태는 구글 시트가 아니라 Apps Script의 스크립트 속성에 저장되며, 새로 접속하는 사람에게만 즉시 반영됩니다(이미 열려 있던 브라우저 탭은 새로고침해야 최신 상태를 봅니다).

## 항목을 바꾸고 싶을 때

신청서 항목을 추가/삭제하려면 두 군데를 함께 수정해야 합니다.

1. `Code.gs`의 `HEADERS` 배열 (저장될 열 이름 목록)
2. `index.html`의 해당 `<input name="...">` / `<textarea name="...">` (입력값의 `name` 속성이 `HEADERS`의 이름과 일치해야 합니다)

수정 후에는 Apps Script를 다시 배포(새 버전)해야 반영됩니다.

## 알아두실 점

- 관리자 PIN은 **가벼운 접근 제어**이지 강력한 보안 수단은 아닙니다. 링크와 PIN은 센터 내부에서만 공유하시고, 민감한 개인정보(주민번호, 계좌번호 등)는 이 시스템에 수집하지 않는 것을 권장합니다.
- 무료 Apps Script 웹앱은 일일 URL Fetch/실행 시간 등에 할당량이 있지만, 학과 단위 접수량(수십~수백 건) 정도에서는 문제가 없습니다.
- 스프레드시트 한 시트에 데이터가 매우 많이 쌓이면(수만 행 이상) 관리자 화면 로딩이 느려질 수 있습니다 — 학기별로 시트를 분리하거나 지난 학기 데이터를 별도 시트로 보관하는 방식을 권장합니다.
